01 · Brief

 
What we're building, and the one thing that must be true

 
Problem. Creators know their niche but not what will perform. Scripting is their weakest skill. Production (avatar, voice, video) is slow and fragmented across 4–6 tools. Existing AI tools generate assets; none earn trust at the plan stage with evidence.

 
Bet. We win at the plan. If the first plan clicks — concepts with visible rationale, referenced to real high-performing content and stats — everything downstream (creative studio, avatars, voice) converts. If the plan feels like generic ChatGPT output, nothing else matters.

 
V1 is / is not

 

 
 | In scope (v1) | Out of scope (v1)

 
 | Plan → approve → text / image / video ≤30s, 9:16 | Posting, scheduling, platform OAuth

 
 | Two personas: AI-content creator, product-ad (UGC) creator | Analytics ingestion via platform APIs (manual paste first)

 
 | Inspiration DB (curated, ~500 assets at launch) + best-practice corpus | Live trend scraping at scale (ToS risk — see §12)

 
 | Avatar + voice building blocks on fal.ai | Music generation, editing timeline, collab/teams

 

 
Winning factors → what each requires

 

 
Plan that clicks → every concept carries evidence: 1–2 inspiration references + a stat + a red-team pass. Not adjectives.

 
Confidence before generate → Creative Studio never shows a final script first. It shows a Concept Confidence Card: storyline beats, format, why-it-wins, cost. Generate is the second click.

 
Memory → profile + campaign + performance memory; the loop from published results back into the planner is the real moat (§09).

 
RAG → inspiration corpus + best-practices corpus + user's own content. Quality of curation beats quantity.

03 · Planning engine

 
Context + inspiration + evidence → a plan you can defend

 
3.1 User context (form, not chat — chat only for refinement)

 

 
Layout: guided blocks, each with a one-line inline guideline; required vs optional fields marked. Naming is required: user names every series/post at creation — that name is its handle in the Plans tab.

 
Mode: Series or One-time · Content area (AI, product ads, kids' education, viral/general…) · free-text description of what they want to say

 
Purpose: followers / impressions / engagement / conversions (pick primary — planner optimizes one) · target audience · platforms · timeline & cadence · content type (text / text+image / text+video)

 
References ("Teach the engine" block): clear upload tiles — past posts, docs/brief, screenshots, brand assets — each labeled required/optional. Claude's native vision handles them — no separate vision model needed. Extraction result echoed back under the tiles ("style extracted: …") so the user sees what the engine learned.

 

 
3.2 Inspiration DB — what to store, how to fill it answers open point (c)

 

 
 | Per asset | Fields

 
 | Identity | Platform, source link, posted date, creator size band (nano/micro/macro)

 
 | Classification | Niche tags, format taxonomy (talking-head, faceless b-roll, tutorial, skit, listicle carousel, UGC testimonial, unboxing, meme), duration

 
 | Craft | Hook text + hook type (question / bold claim / pattern-interrupt / POV), structure beats, CTA style, thumbnail

 
 | Performance | Views, engagement rate, velocity (views/day first week) — as-of date stamped

 
 | Annotation | Transcript + LLM "why it works" note, written at ingest (Haiku) — this is what makes retrieval useful

 

 
Sourcing (honest version)

 

 
Safe: TikTok Creative Center (public trends/top ads), YouTube Data API (ToS-compliant), brand ad libraries (Meta Ad Library for ad formats), creator-submitted links.

 
Scraper services (updated): logged-out public metadata via Apify / Bright Data is legally defensible after Meta v. Bright Data and X Corp v. Bright Data (both won by the scraper, 2024). Scrape metrics + captions + links; never rehost the videos (copyright is a separate question from scraping). Full pipeline in §10.

 
Baseline: ~500 curated + annotated assets across 6–8 niches at launch; weekly scraper runs + ops QA after. Annotated quality beats raw volume.

 
Card contents (not just a title): format + platform + duration chips · title · 1–2 line content description (what actually happens in the post) · stats line with source_id + as-of · one-line "why it works". Multi-select; selections enter planner context as structured evidence.

 
Wired but disabled at launch: while sourcing is tentative, ship the full card UI on sample data with selection disabled and an honest "sample data — pipeline pending" label. The wiring (retrieval call, evidence handoff) is real; only the corpus is placeholder. No fake liveness.

 

 
3.3 Curated best-practice corpus answers open point (d)

 

 
Official creator-education docs (IG/YouTube/TikTok creator academies, algorithm explainers) — safest, most current.

 
Retention/hook research + hook formula libraries; ad-creative playbooks (e.g. Meta performance creative guidance).

 
Expert teardowns transcribed from public talks/podcasts, tagged by niche and platform.

 
Ingest: chunk 500–800 tokens; metadata {platform, topic, content_type, source_tier}; pgvector + rerank at query. Source-tier weighting so official docs outrank blog spam.

3.8 Concept Confidence Framework (CCF) — the formula behind every plan

 
Card anatomy (locked): Concept (title) → Description (2–3 lines) → Creative direction (what the post will actually contain: format, setting, treatment — ≤40 words) → Hook (verbal line + first frame) → element table. Honesty rule: if an element isn't addressed, the card says not addressed with why — no forced Med ratings. The planner proposes scores; the feedback agent owns the final rating. Final CCS > 70 unlocks exactly 3 creative options per post — distinct angles, each scored. Below 70 → rework loop. Creative work always ships as choices, never a single take.

 

 
 | Element | What it asks | Evidence that counts

 
 | Hook strength | Do the first 1–3s stop the scroll — visually (works on mute, ≤3 objects) and verbally (problem, claim, or curiosity gap)? | REF: proven hook pattern in inspiration DB · corpus first-frame rules

 
 | Audience alignment | Is this a documented pain/interest of the target audience, not an assumed one? | STAT: niche×format benchmark · TREND: keyword velocity

 
 | Retention structure | Does the shape hold to the end — foreshadow, beats, payoff/twist, loop? | Corpus formulas (hook→foreshadow→narrative→twist) · retention benchmarks

 
 | Differentiation | Fresh angle, or the 400th version? Red-team runs the saturation check against the inspiration DB. | REF: similarity count in DB, dated

 
 | Distribution triggers | A concrete reason to share, save, or comment — utility, identity, emotion. | Format-level share/save benchmarks

 
 | Platform-format fit | Native to the platform and proven in this niche? | STAT: native-style engagement research · format benchmarks

 
 | Creator fit & feasibility | Matches the user's voice, assets, capacity? A great concept the creator can't execute scores Low. | Profile memory + asset inventory

 
 | Persuasion & proof ads only | Claim strength, on-screen proof, objection handling, single clear CTA — within brand's approved claims. | Brand brief compliance · ad-format benchmarks

 

 
Weights by objective (v1 priors)

 

 
 | Element | Followers / reach | Engagement | Conversions (ads)

 
 | Hook strength | 25 | 20 | 25

 
 | Audience alignment | 15 | 15 | 15

 
 | Retention structure | 15 | 15 | 10

 
 | Differentiation | 15 | 10 | 10

 
 | Distribution triggers | 10 | 20 | —

 
 | Platform-format fit | 10 | 10 | 10

 
 | Creator fit & feasibility | 10 | 10 | 10

 
 | Persuasion & proof | — | — | 20

 

 

 
Scoring: High=3, Med=2, Low=1, not-addressed=0. CCS = Σ(weight × score)/3. Gates: final CCS > 70 → qualified, 3 options generated per post · ≥85 flagged "strong" · ≤70 → rework with the feedback agent's fixes.

 
Hard gate: Hook = Low → rework regardless of composite. A dead hook makes everything downstream irrelevant — hook is multiplicative, not additive.

 
Evidence rule (hard): agents have no web search and may not answer from memory. Every rating cites a DB-resolvable source_id (asset:/chunk:/stat:/trend:) retrieved in-run; the validator rejects unresolvable citations. Empty retrieval → "no evidence in DB", shown honestly. Model heuristics allowed only as PRINCIPLE, rendered muted.

 
Feedback mechanics: the feedback agent is the final rating authority — it must verdict every element (agree / downgrade / upgrade, with reason + evidence or a declared evidence gap). Planner proposes, feedback agent disposes; downgrades stay visible on the card.

 
Honesty: v1 weights are expert priors from the corpus, not learned. Recalibrate from performance memory once ≥200 scored concepts have real results. CCS is structured judgment that forces evidence — not a virality predictor. Never market it as one.

 

 
3.9 Agent output schemas & validation

 
Five contracts, pydantic-enforced. Invalid output → agent re-run with the validation error (max 2 retries) → hard fail surfaced to user. Never silently accepted, never silently repaired.

 

 
 | Agent | Input | Output schema | Hard validations

 
 | Intake | Form fields + uploads | CreatorContext | Enums valid · ≤3 clarifying questions · no advice fields

 
 | Planner | CreatorContext + selected asset_ids (+ Feedback on refine pass) | Plan | Every element present or addressed=false with reason · every evidence item has resolvable source_id · slots match cadence · refine pass may touch only flagged concepts (diff-checked)

 
 | Feedback | Plan | Feedback | Verdict on ALL elements of every concept + 4 lenses (saturation, claims/brand safety, feasibility, platform policy) — any missing = invalid · downgrades need reason + evidence or evidence_gap=true · ccs_final computed and re-checked server-side

 
 | Planner — variants pass | Concepts with ccs_final > 70 | Options[3] | Exactly 3 · distinct angle_labels · each independently scored

 
 | Creative director | Approved option | ConfidenceCard → ScriptPackage | Card exists before script · every shot ≤8s · identity + wardrobe/lighting locks verbatim in every keyframe_prompt · cost estimate present · closing_shot slot present

 
 | Brand-kit composer | Uploaded assets OR pre-extracted brand data | BrandKit | 2–3 options · message ≤7 words · logo never redrawn, only overlaid

Verdict on ">10s = front-end script to stitch"Don't stitch on the front end. Client-side (WebCodecs/ffmpeg.wasm) is fragile across devices and kills mobile. Two correct routes: (a) Veo 3.1 extend-video chains a clip natively to 30s — fewer seams, higher cost; (b) shot-wise i2v + server-side ffmpeg (worker container) — cheaper, full control of cuts and VO. Ship (b) as default, (a) as premium "one-take" option.

 
Rules

 

 
Text-only concepts finish in Content Studio — never force Creative Studio.

 
Every generate click shows cost estimate first (credits). Drafts render 1 shot before committing the full reel.

 
Character consistency across shots: generate keyframes from one avatar reference via Nano Banana multi-image edit; feed keyframe → i2v per shot. Expect drift; expose "re-roll shot" not "re-roll reel".

 
The studio is a conversation, not a wizard. The step flow above is the agent's internal sequence. UI: user lands in a thread with the concept pre-loaded; agent opens with the confidence card; approvals, tweaks and re-rolls all happen in-thread; a persistent prompt modal sits at the bottom (DS prompt-bar pattern: radius-20 container, attach button, model pill, 32px send). No step tabs.

 
Sidebar = past threads/series only (+ New thread · DIY, which is the same tools with no agent).

 
On final approval the deliverable — creative file(s) + text (caption/copy/description) — is posted in-thread and saved to My Space for download.

 

 
Character consistency & shot integration (Veo 3.1)

 

 
 | Route | Recommended for | How | Trade-off

 
 | One-take | Talking-head, monologue, single scene | Veo 3.1 t2v/i2v with native audio + extend-video chained to 30s | Best continuity, highest cost, least shot control

 
 | Keyframe cuts | Listicle, multi-scene, tutorial | Identity-pack keyframes (NB2 multi-ref) → i2v per shot → hard cuts + VO in stitch | Cheapest; drift risk between scenes

 
 | Interpolated flow | Product demo, transition-heavy | Veo 3.1 first/last-frame interpolation between adjacent keyframes | Smoothest seams, mid cost

 

 

 
Recommendation, not decision: the creative director recommends a route from content type + context, with a reason. The user picks. Routes are never switched silently.

 
Identity pack: 3–5 reference images per avatar; wardrobe + lighting descriptors locked and repeated verbatim in every keyframe prompt.

 
Seam QA: embedding-similarity check on each shot's boundary frames; below threshold → shot flagged for re-roll before stitch.

Shared agent policy (prepended to all)

EVIDENCE & HONESTY POLICY — applies to every agent
1. You have no web search and no browsing. Do not simulate one.
2. Every factual claim about performance, formats, audiences, or trends must cite a
 source_id returned by YOUR retrieval tools in THIS run (asset:* / chunk:* / stat:* / trend:*).
 Citations that don't resolve against the DB fail validation.
3. If retrieval returns nothing relevant: write "no evidence in DB" and set
 evidence_gap=true. Never approximate a number. Never invent an asset or stat.
4. General knowledge is allowed only as tag=PRINCIPLE with source_id="model".
 Principles are opinions, not data. Do not dress them up as data.
5. Output strict JSON matching your schema — no markdown, no prose outside JSON.
 On validation error you are re-run with the error; fix only what is invalid.
6. Never fabricate user context. Missing input stays null.
7. Audience: Indian + global creators. No claims that violate platform ad policy.

 
1 · Intake agent (Haiku 4.5; Sonnet when files attached)

You normalize raw user input into CreatorContext JSON: form fields, pasted text,
and uploads (video frames, screenshots, docs).
- From uploads, extract only what is visible: style, tone, format, pacing,
 captions, avatar presence. Describe. Do not guess metrics or performance.
- Map free text to enums; anything unmappable goes to notes[], not forced enums.
- Unknown required fields → null + add to clarifying_questions[] (max 3, only
 if truly blocking).
- You give no advice, no ideas, no plan. You are a parser with eyes.
OUTPUT: CreatorContext v1.

 
2 · Planner agent (Sonnet 4.6)

You are the Planning Agent. Build a content plan a strategist would defend
line by line in front of the creator.
TOOLS: search_inspiration, search_corpus, get_benchmarks, get_trends, get_profile.
PASS 1 — CONCEPTS
- Produce concepts for every slot in the cadence. Each concept: title,
 description (2–3 lines), creative_direction (what the post will contain:
 format, setting, treatment — ≤40 words), hook {verbal line, first_frame},
 format, platform, cta, effort, asset_needs.
- Score every applicable element (8 for conversions, else 7) with
 proposed_rating + how_addressed + evidence[]. If an element is genuinely
 not addressed: addressed=false, why_not, rating null. Do NOT force a Med.
- Respect pillar_mix and stated capacity. A concept the creator cannot
 produce is invalid, however good it looks.
- You propose ratings. The feedback agent decides them. Do not compute ccs.
PASS 2 — REFINE (input: Feedback)
- Change only concepts/elements the feedback flagged. Log changes[].
 Untouched concepts must be byte-identical (diff-checked).
PASS 3 — OPTIONS (input: concepts with ccs_final > 70)
- Exactly 3 options per concept: distinct angle_label, hook,
 creative_direction_delta. Different approaches, not reworded copies.
OUTPUT: Plan v1 / Options v1.

 
3 · Feedback agent — red team (Sonnet 4.6)

You are the Feedback Agent and the FINAL RATING AUTHORITY.
Persona for this run: {dynamic_persona} — built from target audience,
platform behavior, and niche norms. Judge as that audience, not as an AI.
TOOLS: search_inspiration, search_corpus, get_benchmarks.
For EVERY concept:
- Verdict on EVERY element: agree / downgrade / upgrade → final_rating.
 Each non-agree needs a reason + evidence[] or evidence_gap=true.
- Four mandatory lenses: (a) saturation — run similarity retrieval, cite the
 count and source_id; (b) claims & brand safety; (c) feasibility vs the
 creator's stated capacity; (d) platform policy.
- kill_flags: hook=Low, unsubstantiated claim, policy risk. A kill_flag
 blocks options regardless of score.
- fixes[]: ordered by impact, each a concrete change, not "make it better".
- Missing any element or lens = your output is invalid.
You give feedback only. You never rewrite concepts. Server recomputes CCS.
OUTPUT: Feedback v1.

 
4 · Creative director (Sonnet 4.6 — studio thread)

You run Creative Studio for one approved option. The sequence is fixed:
1. CONFIDENCE CARD first: storyline beats (not the script), the option's

2. After approval: ScriptPackage — vo_script, shots (each ≤8s) with

14 · Risks & open calls

 
What kills this, in order

 

 

1 · Unit economics

$5–13 per finished reel at current fal prices. Unlimited plans are impossible; credits + draft-tier are structural, not optional. Google can reprice Veo under us at any time.

 

2 · Weak moat at plan layer

ChatGPT writes content plans free. Our defense = annotated inspiration DB + performance loop + one-flow production. If curation ops slips, the plan degrades to generic and the bet dies.

 

3 · Inspiration DB legality — narrowed, not closed

US courts backed logged-out public scraping (Meta and X both lost to Bright Data, 2024), so the metadata pipeline is defensible. Residual: platform IP-blocking and account bans (use third-party scrapers so that risk sits with them), copyright if we rehost videos or full transcripts (we don't), and personal-data law (GDPR / India DPDP — store content metrics, not people data).

 

4 · Likeness & voice consent

Uploaded faces and (later) voice cloning need consent attestation, celebrity-lookalike blocking, and a misuse policy pre-launch. One deepfake incident defines the brand.

 

5 · Multi-shot consistency

Character drift across shots is unsolved. Mitigate: NB2 reference-locked keyframes, per-shot re-roll, honest "AI look" positioning for v1. Don't promise brand-film fidelity.

 

6 · Crowded market

Creatify, Higgsfield, createpersona et al. own "generate an avatar video". Nobody owns "evidence-backed plan → production". Positioning must lead with the plan, or we're a thinner Higgsfield.

 

 
Open calls for review

 

 
Pricing currency: INR-first credits vs USD — affects target segment (India creators vs global).

 
Kabir batch A/B volume in v1 or v1.5 (adds batch infra + cost exposure).

 
Name/trademark clearance for Plotline (or pick alt).
