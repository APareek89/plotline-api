PRD Addendum 03 · Marketing Studio UI · changes only

Nav, campaigns grid, My Brand, reference media

Owner: Anand · 24 Aug 2026 · Applies over system-prompt v2 (and PRD v1 + Addenda 01–02 behind it). Where this conflicts with v2, this wins. Ship to Claude Code together with marketing-studio-demo.html — the HTML is the design contract (§07), this document is the behavioral spec.

01 · Navigation & studio sub-bar

Three global tabs, one studio-scoped action

  • Global nav: Campaign Studio · My Campaigns · My Brand (new, §03). Nothing else at global level.
  • "+ New campaign" moves out of the global nav into a slim studio sub-bar directly under the top bar, visible only inside Campaign Studio: left = breadcrumb ("Campaign Studio · <current campaign name>"), right = + New campaign (dashed pill). Always available mid-flow; starting a new campaign from it confirms nothing is lost — the current campaign persists in My Campaigns at its last state.
  • If a Brand profile exists (§03), a new campaign's Brand card opens pre-filled; the sub-line under the three detail cards says "Brand will pre-fill from My Brand ✓".

03 · My Brand tab (new)

One brand profile, filled once, used everywhere

brand_profile {
  id, name, url,
  palette[4], font, logo_url, tone_rules,
  policy_doc_ref?,                    // uploaded brand policy document
  approved_claims[{id, text, confirmed:true}],   // user-confirmed — compliance source of truth
  banned_words[],
  fetched_from_url: bool, updated_at
}
  • Empty state: two actions — Pre-fill from URL (runs the same extractor pipeline, then opens the Brand modal for confirmation) and Add manually. Both reuse the exact Brand modal from the campaign flow with a standalone save.
  • Saved state: read view — palette swatches, font/logo, tone, policy doc, claims (green) + banned words (red) — with Edit / refetch. Editing re-opens the modal; claims edits require re-confirmation taps.
  • Bidirectional pre-fill: saving a Brand card inside any campaign creates/updates the profile; every new campaign's Brand card pre-fills from the profile and is labeled "Pre-filled from My Brand ✓". Campaign-level edits ask once: "update My Brand too, or this campaign only?"
  • v1 scope: single brand. "+ Add another brand" renders disabled-with-tooltip (multi-brand = later phase; agencies need it, don't fake it now).
04 · Reference media in Campaign Details

User reference beats template

  • Campaign Details modal gains Reference image / video (optional) — up to 3 files, stored as reference_media[] on CampaignContext.
  • Semantics: passed to planner + creative orchestrator as a creative reference (style, composition, pacing). Priority order when both exist: user reference > selected template; the templates step says so inline. Reference never overrides brand palette/claims — style only.
  • Surfaced honestly: rumination log notes "reference video noted"; Context tab gets a Reference media row ("1 video (user) — priority"); the model-confirm card inherits nothing new.
05 · Prompt modal

No model names in the bar

Final anatomy: + upload (attach counter "Images 0/8") · prompt field · ⚙ Settings (disabled, tooltip "Model selection coming — using recommended") · blue send. No LLM or media-model label anywhere in the bar. The media model appears exactly once: in the in-thread model-confirm card at generate time, with its reason and cost. LLM identity is never user-facing.
